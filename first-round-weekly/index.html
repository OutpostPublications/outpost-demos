Can The Weekly stay all-Ghost?

Yes, happily — with a few honest trade-offs. Below is a hand-built simulation of the closest Ghost gets to the mint version of the design, using only things Ghost already ships: per-newsletter settings, native editor cards, and three reusable HTML blocks. And nobody writes those blocks by hand — the companion snippet generator turns simple form fields into ready-to-paste markup with one copy button. No forked Ghost, no outside email service, and nothing here touches theme templates, so it works identically on the sister site.

The win: everyone stays in the Ghost editor they already know, keeps every publishing feature they rely on, and lands most of what the design wants. Every region below is numbered and mapped to what produces it, and the parts Ghost simply won't do are spelled out in the fine print at the bottom — worth one read now so nobody is surprised later.

  • Setting

    Configured once in Ghost Admin → Newsletters. The Weekly gets its own newsletter with its own sender, header image, fonts, and colors.

  • Native

    Typed weekly in the editor — normal paragraphs, headings, lists, images. Safe for any editor, styled by Ghost.

  • Snippet

    Pasted weekly as an HTML card, but written by the snippet generator, not by hand. Editors fill out form fields and copy finished markup; every boxed layout in the design comes from here.

The simulation

What a Monday send would look like in a light-mode inbox. Brand fonts appear only inside region 1 — that whole block is a picture. From region 2 down, everything renders in Ghost's own email fonts (system sans here), because email clients don't load webfonts. That boundary is the single most important thing to show the team.

  1. 1Setting

    The masthead is one static PNG, uploaded once as the newsletter's header image. It's the only place the brand faces (Leif italic, Skandia) survive, because it's a picture. The date and author can't live inside it — they change weekly and would mean re-exporting the image every Monday. The sender name and subject line are also per-newsletter settings.

  2. 2Native

    The post title and byline are Ghost's, non-negotiable. The title can't be hidden; font, size, and alignment come from a fixed settings menu. Typed fresh each week, rendered Ghost's way — this is why the masthead image stays dateless and the title carries the date instead.

  3. 3Native

    Ordinary editor content — headings, bold lead-ins, paragraphs. Note the heading sits left: Ghost's email headings don't center. Centered section heads only happen inside snippets (see 5 and 6).

  4. 4Snippet

    Snippet C — hairline list. A plain native bullet list works fine, but the design's ruled rows between items need an HTML card. Each week: type the rows into the generator, copy, paste.

  5. 5Snippet

    Snippet A — quick-notes boxes. The bordered cards with emoji headers and bullets inside. Ghost's native callout card gets close but can't hold bullet lists, so this is table-and-inline-style HTML, written by the generator from form fields. The centered "A few quick notes…" header rides inside the block.

  6. 6Snippet

    Snippet B — decision card. The INVEST/PASS chip is an inline-styled span; in the generator, add a card per company and flip the INVEST/PASS switch.

  7. 7Native

    A normal image card. Photos, captions, and full-width images are the one place Ghost email needs no tricks at all.

  8. 8Setting

    Ghost's footer. Unsubscribe and address lines are generated per-member and can't be redesigned — only the small custom footer text is editable.

The snippet kit

Email-safe HTML — tables and inline styles only, brand hex values baked in. These are the exact blocks the simulation above renders, and exactly what the generator writes from its form fields — shown here so the approach is inspectable. They're theme-independent: the same blocks work on the sister site unchanged.

Weekly use: fill out the generator, hit copy, then in the Ghost editor type /html and paste; click away and the card previews right in the editor. Fallback without the generator: save any block below as a Ghost snippet (⋮ menu → Create snippet) and edit its text carefully. If the web version gets its own theme treatment, set the card's visibility to email only.

The fine print

  1. This is a hand-built simulation, not a Ghost send. It mirrors Ghost's email skeleton faithfully, but the deal isn't done until these settings and snippets go into a staging Ghost and real test emails land in Gmail and Outlook.

  2. The masthead is a picture, and stays dateless. Brand typography exists only inside that PNG. Putting the date, author, or the dark-green pill chips inside the header (versions 1–2 of the design) would mean a designer re-exports the image every single week.

  3. Ghost's title block is immovable. Every issue shows a Ghost-styled post title and byline under the masthead — it can't be hidden, and its styling comes from a fixed menu of fonts and alignments, not the brand faces.

  4. Raw HTML still sits under the hood. The generator writes it from form fields, so in normal use nobody edits tables by hand and the markup is valid every time. The honest remainder: anyone who does hand-edit an HTML card can still break it silently — one deleted </table> scrambles the layout with no warning before send. House rule: content changes go through the generator, and any hand-edit earns a test email.

  5. Email clients get a vote. Outlook on Windows squares off every rounded corner. Gmail clips messages over ~100KB — a long issue full of inline-styled snippets can hit that. And Gmail's dark mode recolors the mint and pale backgrounds on its own terms.

  6. Fonts below the masthead are Ghost's menu, not Skandia. The body renders in whichever font the newsletter setting picks — the system sans shown here is the closest neighbor. Accept the drift; no email platform fixes this without images.

  7. The website version is where the design actually wins. Cards can be marked email-only or web-only, so these table hacks never leak onto the site — and the site's version of The Weekly can match the design pixel-for-pixel, because there the theme is in charge.

  8. Ceiling, stated plainly: this approach lands roughly the mint variant of the mock — masthead, boxed notes, badges, ruled lists — and does not land the dark-green chip header, custom typography in text, or exact spacing. If that last 20% ever becomes non-negotiable, the answer changes from settings-and-snippets to leaving all-Ghost, which the team has already ruled out.

Built from the theme's own design tokens — mint #21FBAC, pine #243C39, paper #FBFBF6, Leif and Skandia from the repo's font files — so the masthead here can be exported as the actual header-image PNG.
