A prettier Changelog, still all-Ghost

Ghost's email design won't get the changelog all the way to "pretty" on its own, and the sections that would help most (count chips, feature callouts, boxed category lists) are exactly the ones that are annoying to build in the editor every release. The fix is the same one that worked for The Weekly: three reusable HTML blocks, written by the companion snippet generator from plain form fields, pasted into the release post as /html cards. Nothing else changes: same Ghost site, same NASA hero images, same emoji-first items, same footer.

Below is a hand-built simulation of Release 3.17 sent that way. Every region is numbered and mapped to what produces it, the exact block markup is inspectable in the kit, and the honest limits are in the fine print.

  • Setting

    Configured once in Ghost Admin → Newsletters: sender, header, fonts, colors, footer text.

  • Native

    Typed each release in the editor: the title, the hero image card, the intro riff. Unchanged from how the changelog is written today.

  • Snippet

    Pasted each release as an HTML card, but written by the snippet generator, not by hand. Paste your item lines into its form and it returns finished markup with one copy button.

The snippet kit

Email-safe HTML: tables and inline styles only, brand hex values baked in. These are the exact blocks the simulation above renders, and exactly what the generator writes from its form fields, shown here so the approach is inspectable. Category chip palette: Added #8340B9 · Improved #E052A5 · Changed #F2A33C · Fixed #2E9E6B · Removed #CD3824 · Security #1F2937; white ink on Added, Removed, and Security, dark ink on the lighter three, so every chip passes AA contrast at chip size.

Per release: fill out the generator, hit copy, then in the Ghost editor type /html and paste; click away and the card previews right in the editor. Fallback without the generator: save any block below as a Ghost snippet (⋮ menu → Create snippet) and edit its text carefully. The changelog post doubles as the web page, including the dark theme: boxed blocks carry a white background and unboxed text inherits the theme color, so the same card works in both places.

The fine print

  1. This is a hand-built simulation, not a Ghost send. It mirrors Ghost's email skeleton faithfully, but the deal isn't done until these blocks go into a real release post and test emails land in Gmail and Outlook.

  2. The title block is Ghost's and stays where it is. Fine here: the "Release X.Y: Codename" convention already does the masthead's job. The at-a-glance chips can't ride above the title, because Ghost content always starts below the byline.

  3. Raw HTML still sits under the hood. The generator writes it from form fields, so in normal use nobody edits tables by hand and the markup is valid every time. Anyone who does hand-edit an HTML card can still break it silently: one deleted </table> scrambles the layout with no warning before send. House rule: content changes go through the generator, and any hand-edit earns a test email.

  4. Email clients get a vote. Outlook on Windows squares off every rounded corner and ignores the left accent border's radius. Gmail clips messages over ~100KB; a sixteen-fix release with three blocks sits nowhere near that, but the generator meters it anyway. Gmail's dark mode recolors the chip backgrounds on its own terms; the palette was picked to keep contrast when it does.

  5. The changelog post is also the web changelog, and the site's theme runs dark. The blocks are built for that: boxed blocks bake their own white background so their dark ink always has something to sit on, and unboxed text (section headers, the lead line) bakes no color at all, inheriting dark-on-white in email and the theme's own color on the web. The cost is that on the dark site the boxes read as white cards, which is intentional, not drift. If anyone prefers the web changelog on native lists, each HTML card can be set to email-only visibility instead.

  6. Emoji are content, not markup. The generator preserves whatever emoji leads each line and never adds its own. Keep writing them; they're doing the visual work bullets used to do.

  7. Ceiling, stated plainly: this approach lands chips, callout cards, and ruled boxes inside Ghost's own email frame. It does not land custom fonts, a redesigned title block, or layout outside the 600px column. If that ever becomes the ask, the answer changes from snippets to a custom email pipeline, which is a much bigger conversation.
